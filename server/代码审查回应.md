## ✅ 已修复的中等问题（Major）

### 4. 🟠 资源泄漏风险 - 已修复

**专家指出的问题**：
- 数据库连接未在异常时正确关闭
- 缺少 try-finally 保护

**我们的修复**：
✅ **添加上下文管理器**：
```python
@contextmanager
def get_db_safe():
    """安全的数据库连接上下文管理器"""
    conn = None
    try:
        conn = get_db()
        yield conn
    finally:
        if conn:
            conn.close()
```

✅ **重构关键函数**：
以 `set_client_baseline` 为例，添加完整的 try-except-finally：
```python
conn = None
try:
    conn = get_db()
    # ... 操作
    conn.commit()
except Exception as e:
    if conn:
        conn.rollback()
    raise
finally:
    if conn:
        conn.close()
```

**影响范围**：
- `server/app.py` (第135-168行 - 添加上下文管理器)
- `server/app.py` (第1603-1663行 - 重构示例函数)

---

### 5. 🟠 并发配置全局可变 - 已修复

**专家指出的问题**：
- 全局配置 `COLLECT_CONFIG` 被临时修改
- 多线程环境下可能导致竞态条件

**我们的修复**：
✅ **避免修改全局状态**：
```python
# ❌ 旧方式（不安全）
COLLECT_CONFIG['max_workers'] = max_workers

# ✅ 新方式（安全）
local_collect_config = {
    'max_workers': max_workers,
    'timeout': timeout,
    'retry_times': COLLECT_CONFIG['retry_times']
}
# 传递局部配置副本
```

✅ **创建新的采集函数**：
```python
def collect_single_client_with_config(client_id, local_ip, config):
    """使用指定配置，避免全局状态污染"""
```

✅ **添加参数验证**：
```python
max_workers = max(1, min(max_workers, 200))
timeout = max(5, min(timeout, 60))
```

**影响范围**：
- `server/app.py` (第641-692行 - 新增函数)
- `server/app.py` (第983-1050行 - 重构批量采集)
