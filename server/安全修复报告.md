## 🔧 详细修复内容

### 1. 移除硬编码敏感信息 ✅

**问题**：
- 数据库密码硬编码在 `app.py` 和 `config.json`
- Session密钥硬编码
- 登录密码明文存储

**修复方案**：

#### a) 添加环境变量支持
```python
# 优先从环境变量读取
MYSQL_CONFIG = {
    'password': os.environ.get('DB_PASSWORD') or db_config.get('password', ''),
}

LOGIN_CONFIG = {
    'password': os.environ.get('LOGIN_PASSWORD') or CONFIG.get('login', {}).get('password', '')
}

app.secret_key = os.environ.get('SECRET_KEY') or secrets.token_hex(32)
```

#### b) 创建配置模板
- `.env.example` - 环境变量示例（可提交到Git）
- `.env` - 实际配置（已加入.gitignore）

#### c) 启动时检查
```python
if not LOGIN_CONFIG['password']:
    print("⚠️  警告: 未配置登录密码！")
    
if not MYSQL_CONFIG['password']:
    print("⚠️  警告: 未配置数据库密码！")
```

**影响文件**：
- `server/app.py` (第28-107行)
- `server/.env.example` (新建)
- `server/requirements.txt` (添加 python-dotenv)
- `.gitignore` (添加 .env)

### 2. SQL注入防护 ✅

**问题**：
- `sort_by` 和 `order` 参数直接拼接到SQL
- 批量操作未验证输入长度

**修复方案**：

#### a) 白名单验证（已有，确认有效）
```python
# app.py 第816-821行
valid_sort_fields = ['hostname', 'local_ip', 'group_name', 'last_report', 'created_at']
if sort_by not in valid_sort_fields:
    sort_by = 'last_report'

order = 'DESC' if order.lower() == 'desc' else 'ASC'
```

✅ **确认**：此处的SQL拼接是安全的，因为使用了白名单验证。

#### b) 批量操作限制
```python
# 限制批量操作数量
MAX_BATCH_SIZE = 1000
if len(client_ids) > MAX_BATCH_SIZE:
    return jsonify({'error': f'批量操作数量不能超过{MAX_BATCH_SIZE}个'}), 400

# 验证client_id格式
import re
for cid in client_ids:
    if not re.match(r'^[a-zA-Z0-9_-]+$', str(cid)):
        return jsonify({'error': f'无效的客户端ID: {cid}'}), 400
```

**影响文件**：
- `server/app.py` (第1472-1495行)

### 4. 资源泄漏修复 ✅

**问题**：
- 数据库连接未在异常时正确关闭
- 缺少 try-finally 保护

**修复方案**：

#### a) 添加上下文管理器
```python
from contextlib import contextmanager

@contextmanager
def get_db_safe():
    """安全的数据库连接上下文管理器"""
    conn = None
    try:
        conn = get_db()
        yield conn
    finally:
        if conn:
            try:
                conn.close()
            except:
                pass
```

#### b) 重构关键函数
以 `set_client_baseline` 为例：
```python
conn = None
try:
    conn = get_db()
    # ... 数据库操作
    conn.commit()
    return jsonify({'status': 'success'})
except Exception as e:
    if conn:
        conn.rollback()
    return jsonify({'error': str(e)}), 500
finally:
    if conn:
        conn.close()
```

**影响文件**：
- `server/app.py` (第135-168行 - 添加上下文管理器)
- `server/app.py` (第1603-1663行 - 修复 set_client_baseline)

### 5. 并发安全修复 ✅

**问题**：
- 全局配置 `COLLECT_CONFIG` 被临时修改
- 多线程环境下可能导致竞态条件

**修复方案**：

#### a) 避免修改全局配置
```python
# ❌ 旧代码（不安全）
old_workers = COLLECT_CONFIG['max_workers']
COLLECT_CONFIG['max_workers'] = max_workers  # 修改全局状态
# ... 使用
COLLECT_CONFIG['max_workers'] = old_workers  # 恢复

# ✅ 新代码（安全）
local_collect_config = {
    'max_workers': max_workers,
    'timeout': timeout,
    'retry_times': COLLECT_CONFIG['retry_times']
}
# 传递局部配置，不修改全局状态
```

#### b) 添加参数验证
```python
# 限制参数范围
max_workers = max(1, min(max_workers, 200))  # 1-200
timeout = max(5, min(timeout, 60))  # 5-60秒
```

#### c) 创建新的采集函数
```python
def collect_single_client_with_config(client_id, local_ip, config):
    """使用指定配置采集，避免全局状态污染"""
    # ... 使用传入的 config 而非全局 COLLECT_CONFIG
```

**影响文件**：
- `server/app.py` (第641-692行 - 新增函数)
- `server/app.py` (第983-1050行 - 重构 collect_all_clients)

### 6. 缺少速率限制 ⏸️

**建议方案**：
使用 `flask-limiter` 中间件实现速率限制：

```python
from flask_limiter import Limiter
from flask_limiter.util import get_remote_address

limiter = Limiter(
    app=app,
    key_func=get_remote_address,
    default_limits=["200 per day", "50 per hour"]
)

@app.route('/api/login', methods=['POST'])
@limiter.limit("5 per minute")  # 登录接口限制更严格
def api_login():
    ...
```

**原因**：此功能需要额外依赖，且不影响当前安全性，可以后续迭代添加。
